# STRATEGY — 外链建设（第一版）

> 对应「游戏站交付看板」十三、增长 · 第 51 项「外链建设」（原状态 `❌ 缺失`，现做法「完全没有」）。
> 本文是**第一版**，目标是先把口径、来源清单、执行节奏和红线定下来；跑满一个月后用真实数据改第二版。
> 写于 2026-10-27。数据类断言都标了来源；没有来源的一律写「待验证」。

---

## 一、为什么现在要做

我们的 48 个站全部是 `*.vercel.app` 子域。截至 2026-10-27 的实测：

- **内容**：单站攻略 7–50 篇，中位 20 篇；
- **流量**：看板里取得到数据的 46 站，30 天总 PV **13,969**，中位 **142**；其中 **21 站 PV < 100**、24 站在 100–1,300、1 站 2,417（来源：`dashboard /api/traffic`，2026-10-27；另 2 站看板无数据 = 不可判定，不当 0）。

这个阶段的排名瓶颈不在「再写一篇攻略」，而在**新域名没有任何外部信任信号**：

- `vercel.app` 是共享主域的子域，别人手上有成千上万个同类子域，Google 不会因为它来自 Vercel 就给任何额外信任；
- 我们 48 站用同一套模板、同一批页型、同一批词根，站内优化已经做满（内链、schema、sitemap、H1 门禁），继续加页的边际收益在递减；
- 生财圈内做游戏攻略站的同行把「发外链」当作流水线里**必备的一环**，不是可选项 —— 诗意听涛的全自动化流水线明确写着业务链路是「找词 → 注册域名 → 调研 → 上站 → 自动更新 → 加广告 → **发外链**」（[原帖](https://scys.com/articleDetail/xq_topic/55522542522288884)，2026-06 精华帖，1.2 万阅读）。

也就是说：这不是「要不要做」的问题，是「用哪种做、做到什么程度、怎么不把 48 个站做成一个 PBN」的问题。

## 二、圈内已经验证过的方法（原文提炼）

| 方法 | 出处 | 关键事实 |
|---|---|---|
| 外链库 + bot 定时发 + 定期体检 | 范师傅、良逍（2026-10，推特/公众号） | 把外链分成「导航站 / 博客评论 / 客座文章」三类建库；bot 每天定时发，定期清理失效链接；AI出海范式自述「新站每天 5 条，发一周多 DR 到 10」 |
| Claude Code + Playwright MCP 批量提交 | Yifei易飞（星球帖 45544411281154148） | 3 天 4 站提交 300+ 条独立域名外链，约 40% Dofollow；**DR 是假指标**（DR50+ 的候选全是零流量 PBN），必须用真实流量硬过滤；每条提交后**实测 rel 属性**，平台标注不可信 |
| 抄竞品的外链 | 易焘（星球帖 82811852122811822，精华，1.07 万阅读） | 用免费外链检查工具查对标站的外链 → 按域名去重 → 批量初筛；**要落到具体文章 URL**，先确认竞品那条评论还活着，再去同一篇下发 |
| 竞品反查的正确姿势 | 同 Yifei易飞 | 同一个站不同文章的审核策略不同：拿到精确 URL → 检查竞品链接是否存活 → 存活才在同篇提交，不存活整站跳过；选「评论数 > 50、有老 SEO 评论存活」的文章 |
| 2026 年还在传权重的三类 | 同 Yifei易飞（100+ 平台实测） | ① 开发者博客平台（velog.io 即发即过 / dev.to 正文链接 dofollow / telegra.ph、rentry.co 走 API）；② SaaS 目录提交（listing 页「Visit website」默认 dofollow）；③ 论坛 Profile 的 website 字段（phpBB 默认 dofollow，实测 100%）；**已降级**：paragraph.com、hackmd.io、justpaste.it、codepen.io 等 paste/note 类 |
| 关于 nofollow | 同上 | Google 2019 起把 nofollow 当「提示」，会选择性传递；90%+ dofollow 的比例反而像刷 DR，自然分布更安全；高 DR 站的 nofollow（GitHub、Medium）有品牌信号价值 |
| 付费客座 blog | JsonChao（星球帖 14422515818842542） | 几十条高质量外链累积后才见效；**最大的坑不是贵，是买到垃圾站**（Spam Score 高、一看就是卖链接的站会拖累信任度） |
| 分阶段看指标 | 亿豪（星球帖 55521518444488414，精华） | 第一阶段看「播下去的种子」= 提交量；第二阶段看「外链被收录的数量」，而不是马上看排名 |

**一句话总结圈内共识**：外链是苦活，靠自动化把「提交」这一步的边际成本压到接近 0，但**候选筛选和 rel 实测不能自动化掉**，那两步决定这批链接是资产还是负债。

## 三、我们的口径（和上面的差别）

圈内主流做法是「一个站，几百条外链」。我们不是。我们是一个 **48 站的矩阵**，这带来三个必须不同的约束：

1. **不能追求量。** 48 站 × 300 条 = 14,400 条，任何一批自动化提交都会在来源站留下肉眼可见的同模板 footprint，反而触发 spam 判定。
2. **不能 48 站互相链。** 同模板、同页型、同链接池的站群互链，是最典型的 PBN 特征。内链只在单站内做（已有 `related`），**站与站之间默认不互链**。
3. **单站内容支持不了「内容级」外链的密度。** guest post 要求我们有独特观点可写，中位 20 篇攻略的站撑不起大量投稿；这块只能按「每月全矩阵 2–4 条」的节奏做。

据此定第一版口径：

- **计数单位**：不是「每站 N 条」，而是 **每站 ≥3 条可验证存活（提交后 30 天复查仍在线）的引用域**，全矩阵按周分批推进。
- **时间线**：D+30 看提交量与收录、D+60 看引用域（RD）与进词、D+90 再看排名 —— 与 `docs/STRATEGY-生命周期与止损.md` 的检查点对齐，**外链不单独设止损线**，并入生命周期分级。
- **配对逻辑**：外链只投给「生命周期 A/B 档 + 已上线 ≥30 天」的站，C/D 档和 `不再维护` 的站不投 —— 与扩词轮同一套名单口径（`scripts/expansion-targets.mjs --json` 的 eligible[]），避免把钱花在已验证不行的站上。

## 四、来源清单（游戏攻略站专用）

按「拿链接的成本 / 风险 / 价值」排序。**这一节是第一版里最需要后续用真实数据修正的部分** —— 下列平台的可提交性与 dofollow 状态均**待实测**，第一轮跑完把结果写进台账。

### A 类：目录与 Profile（可自动化，成本最低）

| 来源 | 怎么用 | 风险 | 状态 |
|---|---|---|---|
| 游戏站/工具站导航目录（含 submit 入口、listing 页给「Visit site」按钮的站） | 提交站点 URL + 一句话简介 | 低：只填 URL | 待实测：Yifei 的清单面向 SaaS，游戏攻略站能否过审未知 |
| 开发者博客平台（dev.to、velog.io、telegra.ph、rentry.co） | 把一篇攻略改写成「开发者视角」的短文（如「我怎么自动化生成 48 个攻略站」） | 低–中：内容要真有信息量，纯链接会被删 | 待实测 dofollow 仍然成立 |
| 游戏论坛 Profile 的 website 字段（phpBB 系） | 注册 + 填 profile，不发言 | 低 | 待实测；注意注册门槛与验证码 |
| GitHub 仓库（README 里挂站；对应 fanshifu 提到的「定期更新仓库让 Google 认出是活站」） | 每个游戏一个轻量仓库或一个矩阵仓库 | 低 | 可选，nofollow 但品牌信号强 |

> 2026-10-27 实测：A 类里 **telegra.ph / rentry.co 本机不可达**；dev.to / velog.io / IndieDB /
> gamedev.net 可达但需账号。可达性明细见 `.agent/link-building-p0.md` 第二节。

### B 类：社区与问答（价值高、风险高，只人工/半自动）

| 来源 | 怎么用 | 红线 |
|---|---|---|
| Reddit 对应游戏的子版 | **只回答真问题**，答案里给具体结论，链接作为出处附在末尾；每周全矩阵 ≤5 次 | 多数子版有 no-self-promo 规则，硬广直接封号；`MUST NOT` 用脚本批量发 |
| Steam 社区（讨论区 / 指南） | 玩家提问处给答案 + 链接 | 本机 `steamcommunity.com` 不可达（TCP 被阻断），只能人工或用代理 |
| Quora / GameFAQs | 长尾问答 | 同上，须人工判断相关性 |
| Discord 游戏服 | 只在官方「resources/guides」频道按规则投放 | `MUST NOT` 私信或刷频道 |

### C 类：内容级（见效最慢，价值最高）

| 来源 | 怎么用 | 频率 |
|---|---|---|
| 游戏媒体 / 独立博客的 guest post 或投稿 | 拿我们的一手数据写（如「48 个攻略站 30 天流量复盘」） | 全矩阵每月 2–4 条 |
| 数据页 / 工具页 | 例如「新游攻略站收录速度对比」这类可被引用的页 | 每季度 1 个 |
| 维基类坏链修复 | 找到失效外链，替换成我们的页面 | 只做内容确实覆盖的条目，`MUST NOT` 为了放链接硬塞 |

### 明确不做（写进红线，不进第二版讨论）

- 买 PBN / 链接农场 / 批量「DR 提升」套餐（Yifei 的教训：DR 靠互刷，流量为 0）；
- 批量往不相关 WordPress 博客发评论（哪怕能过 Akismet —— 那是别人的站，不是我们的语境）；
- 48 站互链、同锚文本批量铺（PBN footprint）；
- 用脚本在 Reddit / Discord / Steam 自动发链接（违反平台规则，且账号一旦被封，这些站以后都用不了）。

## 五、执行节奏（第一版）

| 阶段 | 做什么 | 频次 | 产出 |
|---|---|---|---|
| P0（本周） | 建外链台账；挑 5 个 A/B 档站各做 3 条**手工**提交，验证「提交 → dofollow 实测 → 30 天存活」这条链路 | 一次性 | `.agent/link-building-log.jsonl` + 一份「哪些平台真能过」的实测表 |
| P1（第 2–4 周） | 把 P0 验证过、可自动化的来源做成批量提交（Playwright MCP 或纯 HTTP），**每站每周 ≤2 条**，全矩阵每周 ≤20 条 | 每周 | 台账累计到每站 ≥3 条存活 |
| P2（第 2 个月起） | 社区分发（与交付看板第 53 项「社区分发」合并做，不重复投入） | 每周 ≤5 次 | Reddit / Steam 侧的真实回答记录 |
| P3（第 3 个月起） | 内容级外链：用我们自己的流量复盘数据投稿 | 每月 2–4 条 | 1–2 条 C 类外链 |

台账字段（每一条外链一行）：

```
{ "date", "site", "targetUrl", "sourceUrl", "sourceType", "rel", "anchor", "status", "recheckAt", "lastSeenOk" }
```

- `rel` 必须**实测**（提交后打开页面查 `<a rel>`），不填平台宣传值；
- `status` ∈ `submitted / live / dead / rejected`；
- 每 30 天复查一次，`dead` 的比例写进月度复盘；
- 锚文本分布：品牌词 ≥60%、长尾描述 30%、精确匹配 ≤10%（避免过度优化）。

### P0 实测结果（2026-10-27，详见 `.agent/link-building-p0.md`）

已选 5 个起跑站（4 个 `eligible[]` + PV 最高的第 5 站）、排好锚文本、写好复查脚本
`scripts/link-check.mjs`，并实测了 13 个候选平台。**但一条外链也没发出**，两个硬阻塞：

1. **免登录平台全被网络挡住**：telegra.ph、rentry.co、itch.io、quora、medium、gamefaqs、
   steamcommunity 本机 TCP 不通（UDP 53 被投毒且境外 TCP 被阻断，`--doh-url` 也救不回）；
2. **能连上的都要账号**：dev.to / velog.io / gamejolt.com / IndieDB / gamedev.net 均需
   GitHub 或 Kakao 登录（dev.to 还要 API key）。注册要邮箱验证 + 验证码，MUST NOT 由程序代注册。

**所以 P0 的前置条件是「一个可用出口 + 一个平台账号」，不是「再写点脚本」。**
在这两样到位之前，本阶段进度就该停在 0 条，`MUST NOT` 用「已写方案」冒充「已发外链」。

**更新（2026-10-27 晚）**：dev.to 已打通 —— 首篇文章发布，

<https://dev.to/zhaoq0103/running-48-nextjs-sites-from-one-laptop-what-the-tooling-actually-costs-3mkf>

正文 2 条链接线上实测 **dofollow**（`rel="noopener noreferrer"`），已记入
`.agent/link-building-log.jsonl`（`status=live`，`recheckAt=2026-11-26`）。
**dev.to 是目前唯一可用的 A 类通路**；velog / gamejolt / IndieDB / gamedev.net 仍缺账号。
API key 位置 `~/.config/devto/api-key`（600，MUST NOT 入库）。

### 周节奏：每个合适站点每周 1 条（2026-10-27 定）

这是外链这条线**对外承诺的排期**，写在这里也写进 `SOP-游戏攻略站上线.md`，两处说法必须一致。

**「合适站点」= 三个条件同时成立**

1. A/B 档：30 天 PV ≥ 50（D 档止损线是 PV<50，低于它不投外链）；
2. 上线 ≥ 30 天（新站先让 Google 收录，再谈外部信号）；
3. 状态 ≠ `不再维护`（`MUST NOT` 给已停投的站发外链）。

2026-10-27 实测：48 站有数据，其中 **PV ≥ 50 的 30 站**符合条件（PV ≥ 100 的 25 站、
PV < 50 的 18 站不进队列）。这 30 站上线于 2026-06-30 – 2026-08-08，距今 ≥ 80 天，
条件 2 全部满足。数据源 `dashboard /api/traffic`（30 天窗口），名单落在
**`.agent/backlink-queue.md`**，由 `node scripts/backlink-queue.mjs --write` 生成（每周一刷新，`MUST NOT` 手改）。

**产能约束（这条不写死会把账号做废）**

| 项 | 数值 | 依据 |
|---|---|---|
| 目标节奏（平均） | 每个合适站每周 1 条 = 30 条/周 | 本文档定的口径 |
| 单平台单账号上限 | **每周 ≤ 3 篇** |【判断】新账号一周铺 30 篇是教科书级 spam 信号，无实测数据，按保守值执行 |
| 当前可发量 | 1 平台 × 3 = **3 篇/周** | 只有 dev.to 可用 |
| 轮完一遍 | 30 ÷ 3 ≈ **10 周** | 当前产能下的实际周期 |
| 达到 30 条/周需要 | **10 个平台账号** | 30 ÷ 3 |

结论：**「每周每站 1 条」是路线图，不是本周的工作量。** 想真的达标，先扩平台账号
（velog / gamejolt / IndieDB / gamedev.net），而不是先把同一平台的发文量加上去。
在平台数补到 10 个之前，实际执行量就是「平台数 × 3」。

**单篇的硬规矩**

- 一篇 2–3 条链接，指向该站 **top 内页**（不是首页：首页已经在排，外链该推没排上的页）；
- 同一天发的多篇 `MUST` 指向不同站；连续两篇 `MUST NOT` 打同一个站；
- 同一批里锚文本不重复，整体维持品牌 ≥60% / 长尾 30% / 精确 ≤10%；
- 发完立刻 `node scripts/link-check.mjs --write`，rel 以实测为准，不认平台宣传；
- 每站累计到 **3 条存活**才从队列里标 `达标`（与第三节「每站 ≥3 条可验证存活」一致）。

**队列怎么消费**：`.agent/backlink-queue.md` 按「上次发文」升序取，空白的排最前，
同批次内 PV 高者优先。发完只需做两步 —— 在外链台账 `.agent/link-building-log.jsonl` 追加一行、
再跑一次 `node scripts/backlink-queue.mjs --write`；`上次发文` / `存活条数` / `状态` 都是脚本
从台账算出来的，**队列文件本身 `MUST NOT` 手改**。**队列文件是名单的唯一来源**，
`MUST NOT` 凭记忆挑站。

## 六、验收标准

第一版上线后第一个月，用以下四条判断「这条链路是否值得继续投」：

1. **覆盖率**：A/B 档站中 ≥70% 拿到 ≥3 条存活外链；
2. **存活率**：`live / submitted ≥ 60%`（低于这个数说明选源有问题，先修选源再加量）；
3. **收录联动**：拿到外链的站，D+30 GSC 收录率是否高于未做外链的同档站（**对照组**：本轮不做的 C 档站）；
4. **成本**：单条外链平均人工分钟数 ≤5（超过说明自动化没做到位）。

四条里第 3 条是唯一能证伪「外链有用」的证据；如果一个月后第 3 条看不出差异，第二版就该缩小规模、只保留 C 类内容级外链。

## 七、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 站群 footprint | 48 站同模板 + 同一批外链来源 | 外链来源按 3 组错开；每站锚文本与简介文案独立生成 |
| `vercel.app` 子域被来源站拒收 | 部分目录只收自有域名 | 该部分等自有域名迁移后再补（见 `docs/STRATEGY-域名与部署.md`） |
| 平台封号 | Reddit / Steam / Discord 一旦被封不可逆 | 社区类只人工，全矩阵每周 ≤5 次 |
| 与「铺量」节奏冲突 | 每天 5 个新站，外链跟不上 | 新站**上线 30 天后**才进外链队列，不追求同步 |
| 时间被吃掉 | 外链是苦活，挤占内容生产 | 先做 P0 一个人日，验证后再决定是否自动化；`MUST NOT` 在没有 verify 的情况下批量铺 |
