## 一、结论先行

1. **手册与我们最大的共识**：内容必须来自真实信息源，AI 只做「过滤 + 整理」，不做「凭空生成」。
   这一点我们已经在做（事实源清单 + 三级证据），手册把它讲得更直白，可直接作为对外口径。
2. **手册最值得抄的一条**：**页面唯一依据是搜索需求**，一个搜索意图 = 一个内页；
   关键词分组要求 MECE（相互独立、完全穷尽）。我们目前按 P0/P1 分组，
   存在「为完整性建页」的风险（FAQ / tier list 无条件建），需要改成「有词证据才建」。
3. **手册第二值得抄的一条**：**内页清单表 + 固定生成提示词 + 分批生成**。
   我们已有 Agent 管线，但缺一张「词 → 页 → 要回答的问题 → 素材源」的显式清单，
   导致选题靠 Agent 自由发挥，重复与漏项都不好查。
4. **手册第三值得抄的一条**：**模板三层分离**（框架层 / 配置层 / 内容层）。
   我们的事实结构已经是三层（`app/` + `lib/` + `content/`），但模板仍从在运营站复制，
   会带入广告代码与历史内容（已知问题 D13）。应落成独立模板目录。
5. **需要改造后采纳**：手册的「先上线再打磨」和「一个站几十到上百个内页」是**流量窗口逻辑**，
   我们的底线是**内容深度不放松**。两者可以兼容：首批 5–8 页达标即上线，
   D+30 至少补到 15–20 页（原「每周 +5–10 页」节奏不变），D+90 A/B 档补到 30–50 页。

## 二、手册在内容生产上实际讲了什么

### 2.1 关卡 2：页面矩阵

- 新手最大的错误是「只做一个首页等流量」；用户搜的是具体问题（codes / tier list / 某角色怎么获得），
  必须用不同页面分别承接。
- **页面唯一依据是搜索需求，不是「看起来完整」**；不做没人搜的页面。
- 三个需求来源：Google 下拉词、Google Trends 相关词（10–20 个）、SimilarWeb（滞后约 3 天，不作唯一依据）。
- 页面分工：首页承接主游戏词；内页承接长尾词；角色/道具特别多时用一个统一导航页批量展示，不必逐个建独立页。
- 第一个版本只做最核心的页面，不一次性规划所有可能页面。
- **新手站最小页面集：首页 + 10–20 个攻略型长尾问题页**（含 guide 页）。
- 关键词整理规则（可直接抄）：
  - 必须有 `guide` 分类；总数 10–20；
  - 分类禁止「gameplay」「general」这种大空类；Codes 类下只能有一个关键词；
  - 过滤核心主词与非本主题词；同义词合并到搜索量最大、最常用的那个；
  - 不允许非英文词（先翻译）；禁止扩写，只允许改拼写错误；
  - **MECE**：不同分类不互相包含（Guides vs Beginner Guides 属违规）；同分类下不得有单复数等同义词；
  - 每个分类内按流量从大到小排。
- 输出格式 `keywords.json`（categories → keywords），一个关键词一个内页。

### 2.2 关卡 3：素材

- 核心原则：**AI 用于过滤和整理，不用于凭空编造**；事实必须来自真实信息源。
- 首页素材：官方链接、SEO 元数据、主题色（HSL）、多语言优先级、首页各模块文案。
  - 明确约束：只放官方与正经社群链接，**禁止输出 404 链接**；数据为 0 就不写。
- 内页素材：**同一信息至少 2 个来源交叉验证**，全部收进一份按关键词命名的素材文档。
  - 来源 1：Google 搜该内页关键词，取排名前二网页，正文整段复制；
  - 来源 2：YouTube 搜同词，取 2 个「时间较新、观看量较大」的视频，用字幕插件导出字幕，
    交大模型提取关键内容；
  - 来源 3：游戏官网 / Steam 商店页的对应说明，有才复制，没有就跳过。
- 素材文档结构固定：`素材来源地址` + `素材内容`，按来源分段。

### 2.3 关卡 4：生成内容、把站搭出来

- **不要从零搭前端**：找同类型竞对攻略站 → 参考结构 → 打磨成自己的模板。
- **先上线，再打磨**：抢词窗口比完美更重要；「两天上线但抢到先机的站，往往比两周打磨但迟到的站流量多」。
- 参考对象怎么挑：**优先 DR≈0 或很低、排名靠前的新站**——说明它没靠外链，是单靠网页结构把排名顶上去的；
  收集 5–10 个参考对象再选最值得复刻的。
- **抄结构，不抄内容**：页面结构、导航方式、内容组织、配色可以参照；
  文字、游戏名、具体数据必须自己调研，绝不复制。
- 内页写作规格（可直接抄）：
  - title 含关键词，**40–60 字符**；meta description 含关键词，**140–160 字符**；
  - 开头直接回答玩家的搜索问题；全文 **1,200 字左右**；分 H2 小节，每段 3–4 句，适合扫读；
  - 只写调研到的真实信息，不确定标「待确认」；不编造数值、角色名、兑换码。
- 过关标准：本地可访问；AITDK 检查 overview 有 title/description，
  **有且仅有 1 个 H1**，H2/H3 层级正确；首页–导航页–内页结构清晰；PC 端与手机端无空白/错位/溢出。

### 2.4 关卡 7：模板化（三层分离）

- 框架层：布局、页面结构、组件、技术栈、SEO 与多语言生成逻辑——写一次，所有站共用。
- 配置层：游戏名、主题色、官方链接、导航分类、SEO 标题描述、语言——换游戏只改这里。
- 内容层：内页文章、首页文案数据、各语言翻译——每站完全独立。
- 落地动作：游戏特定信息从代码抽到配置文件；内容与导航改动态读取；主题色集中变量；
  sitemap / SEO 由内容自动生成。
- **验收方法：换个游戏名，只动配置 + 内容就能整站切换 → 模板成立。**

### 2.5 关卡 8：批量内页

- 前提：站已模板化，内页 = 往内容目录多放一篇内容文件，框架自动渲染导航 / SEO / 面包屑 / sitemap。
- 三步：
  1. 拿关键词清单反推**内页清单表**：页面名 + 对应搜索词 + 这页要回答什么问题；
  2. 固定一份**内页生成提示词**（结构 + 红线），所有同类页按它产出；
  3. 一组一组喂给 AI，**同类几个一批**，塞多了质量会掉；每批过一遍再放进内容目录。
- **最大的坑：批量 ≠ 灌水**。关键词一换、内容千篇一律 → 老玩家看穿、Google 判低质批量内容降权。
- 判断标准：**能稳定把一个内页写成真实有用的内容，再批量**；不能就先做透单篇。
- 脚本自动化是进阶：先把手动流程跑通，再写脚本；「脚本只加速你已经会做的事」。

### 2.6 关卡 6：数据补页（只取与内容相关的部分）

- GSC 只看五个数：展示量、点击量、平均排名、平均点击率、**搜索词报告**（最重要）。
- 拿到数据第一反应是「这个站还缺什么页面」，**不是再开一个新站**：
  - 有新词但没页面 → 补页；
  - 某页表现好 → 围绕它做关联内容；
  - 页面没被收录 → 查技术、改、重新提交。
- 具体信号：出现 `how to get character X` → 补获取攻略；`best build for Y` → 补配装页；
  `codes 2026` → 更新 codes 页。
- 判断下一步：数据在涨 → 继续补页；做了几周每天个位数访问 → 换下一个词，保留模板与流程经验。
- 广告（仅记录，不改我们的决策）：AdSense 建议日访问 >500 再接，常见被拒原因是内容太少/质量差/缺隐私页；
  Adsterra 审核 1–3 分钟，新手推荐 Native Banner / Banner，**先别选 Popunder**。

## 三、逐条对照与取舍

| # | 手册做法 | 我们的现状 | 判断 | 理由 / 落地位置 |
|:--:|---|---|:--:|---|
| 1 | 一个搜索意图 = 一个内页 | 5 类页型固定建，词→页映射未显式化 | **采纳并改造** | 页型是候选池不是必建清单；每页须有词证据。见 `STRATEGY-内容生产` §2 |
| 2 | 关键词分组 MECE、禁止大空类 | 按 P0/P1 分组 | **采纳** | P0/P1 是优先级，不是语义分组；两者并存：先 MECE 分类，再标 P0/P1 |
| 3 | 最小页面集 = 首页 + 10–20 内页 | 首批 5–8 页 | **改造采纳** | 首批 5–8 保速度，30 天 15–20，90 天 A/B 档 30–50 |
| 4 | 第一版只做最核心页面 | 已有首批 5–8 | **一致** | 矩阵列全量词，首版只做 P0 前 5–8 |
| 5 | 素材同信息 ≥2 来源交叉验证 | 有事实源清单，无「每页 ≥2 源」硬约束 | **采纳** | 每页 ≥2 独立源且 ≥1 官方；素材不足降级或不做。见 §3 |
| 6 | 素材按关键词建文档（地址+内容） | 素材散在报告与对话里 | **采纳** | 新建 `keyword-results/{slug}-sources.md` |
| 7 | AI 只过滤整理，不编造 | 已是红线 | **一致（写进口径）** | 手册原话可直接引用 |
| 8 | title 40–60 / desc 140–160 / 1,200 字 / H2 3–4 句 | 只有 ≥1,200 词 | **采纳** | 补 title/description 长度，进 QA 与构建门禁 |
| 9 | 1 个 H1、层级正确、PC/移动检查 | 构建门禁只看 exit 0 | **采纳** | 加轻量 HTML 检查脚本，见 §5 |
| 10 | 先上线再打磨 | 首批 5–8 页达标才上线 | **部分采纳** | 不追求 UI 完美、不等全矩阵做完；内容最低线不降 |
| 11 | 模板三层分离 | 目录已是三层，但模板从在运营站复制 | **采纳** | 建独立模板目录；验收=换游戏只改配置+内容。见 §5 |
| 12 | 参考 DR≈0 的新站，抄结构不抄内容 | 单一模板，模板差异化暂缓 | **部分采纳** | 不改「一站一模板」现状；做模板 V2 时按此选参考池 |
| 13 | 批量三步 + 同类小批 + 批量≠灌水 | Agent 批量生产，缺显式批次上限 | **采纳** | 每批 ≤5 篇同类；每批 100% 自动化事实检索 + 30% 抽检。见 §4 |
| 14 | 补页优先于开新站 | 有复盘轮，但无「补页配额」 | **采纳** | 每次复盘至少产出 2–3 个补页任务；见 §6 |
| 15 | 数据不涨就换词，保留模板 | 已有 D 档止损 | **一致** | 与生命周期 D 档合流 |
| 16 | 新站先 Adsterra，Popunder 不要 | 已只走 Adsterra（global Social Bar + guide Native） | **部分采纳** | Social Bar 比 Popunder 温和但仍是侵入式；列为 11-25 复盘项 |
| 17 | 多语言最多 4 门，英语必做 | 仅英文（D12 已定） | **暂不采纳** | 先把英文做扎实，与 D12 一致 |
| 18 | same.new / Codex / superpowers 工具链 | 已有自建管线（Claude Code + skill） | **不采纳工具** | 只借「参考站 → 结构复刻」的方法，不换工具 |
| 19 | 角色/道具多用统一导航页 | 无统一导航页 | **待评估** | 矩阵页数 >30 时再评估；先记入 §8 |
| 20 | 首版不追求完美 UI | 模板统一，UI 已稳定 | **一致** | 无动作 |

## 四、对第三阶段（选词）的反哺（只记信号，不改规则）

手册的 DR≈0 判读值得记一笔，但**不进竞争评分**，避免规则反复：

- 手册用 DR≈0 是为了**挑复刻对象**，不是判断竞争强弱；
- 对我们的可用推论：Top 10 里若全是 DR≈0 新站，说明该词「靠结构就能排上去」，
  但也说明**进入者多、窗口短**，应更快上线、更快补页；
- 只有在两个候选**总分相同**时，才把「Top 10 的 DR 分布」当作打破平手的参考，
  且 MUST 在 `selection-{date}.md` 写明取值方式与日期。

> 2026-11-25 复盘时再决定是否转成正式评分项。

## 五、与我们的硬规则冲突点（必须写清）

1. **「先上线」不能变成「先上线再说」**：上线的最低线仍是 5–8 页 / ≥8,000 词 / 单篇 ≥1,200；
   达不到就延后，不许用「抢窗口」当理由降标。
2. **「批量」不能变成「灌水」**：批量前必须证明单页能做扎实（有双源素材、有独立搜索意图）；
   批量后必须过事实检索与抽检，否则退回。
3. **「抄结构」不能变成「抄内容」**：参考站只允许看结构、导航、排版、配色；
   文字、数据、游戏名一律自研，违者按跨站污染处理（QA 直接 FAIL）。
4. **「补页」不能变成「凑页」**：补页必须有 GSC 搜索词或明确长尾词证据，
   MUST NOT 为凑数把同一意图拆成多页（内容自噬）。
