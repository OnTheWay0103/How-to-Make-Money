## 四、完整工作链（三条链路）

```
链路 A — 建站（活跃）：
侦察员（发现+硬筛，`待分析`）
→ 候选分析员（硬门槛 → `需采集` / 直接放弃）
→ 关键词研究员（验证轮，`keyword-results/{slug}.md`）
→ 候选分析员（6 条竞争查询 + 四维评分 + 成本 → `selection-{date}.md`）
→ 主Agent决策（先过否决 `需求>2 且 竞争>1`；再 ≥14 可建 / 12–13 例外需确认 / <12 不建）
→ 关键词研究员（矩阵 + 素材：`{slug}-matrix.md` / `{slug}-sources.md`）
→ 建站协调员 → 站点 → QA审核员 → QA报告 → 主Agent验收 → 部署 → STATS更新

链路 B — 合规改造（活跃）：
主Agent → 合规审计员 → 审计报告 → 主Agent验收 → commit/deploy → 线上验证

链路 C — 运营优化（暂停，定时任务恢复后激活）：
监控员 → monitor-report → 主Agent决策 ──┐
反馈分析师 → feedback报告 → 主Agent决策 ─┤→ 建站协调员（扩充）→ QA → 部署

链路 D — 生命周期（活跃，月度）：
生命周期管理员 → 回填台账 PV/环比 → lifecycle-report（A/B/C/D）
→ 主Agent决策 ─┬→ A 档 → 建站协调员（加码扩充）
                └→ D 档 → 停止投入 + 台账标记「不再维护」（不删站、不改代码）
季度末：生命周期管理员复核 D 档 → 达标者恢复「观察中」
```

## 七、本轮判断：连接（多段文件交接 + 一段核心接力）

## 八、交接协议（文件契约）

### 交接文件契约表

| 交接 | 交接物 | 文件 | 检查方 |
|------|--------|------|--------|

| 候选分析员 → 关键词研究员 | 需采集清单 | CANDIDATE-POOL.md 状态 `需采集` | 研究员按 slug 采词 |
| 关键词研究员 → 候选分析员 | 关键词报告 | keyword-results/{slug}.md | 分析员取 5 个数字 + 攻略型占比 |
| 候选分析员 → 主 Agent | 评分报告 + 池内分数 | keyword-results/selection-{date}.md | 主 Agent 复核依据链后决策 |
| 关键词研究员 → 建站协调员 | 关键词报告 | keyword-results/{slug}.md | 建站协调员检查主题覆盖 |
| 关键词研究员 → 建站协调员 | 页面矩阵（词 → 页 → 意图 → 素材源） | keyword-results/{slug}-matrix.md | 协调员核对 MECE 与 P0 ≥5；QA 核覆盖率 |
| 关键词研究员 → 建站协调员 | 素材文档（每页 ≥2 源） | keyword-results/{slug}-sources.md | 协调员核对 ≥1 官方；QA 复核 |
| 建站协调员 → QA | 站点目录 + SEO 检查结果 | games-site/{site}wiki/（+ 结构层 ERROR 时的 `.agent/seo-fix-<site>.md`） | QA 按 Profile 全检，并复核 `seo-check.mjs --live` exit 0 |
| QA → 主 Agent | QA 报告 | .agent/qa-report.md | 主 Agent 按 PASS/FAIL 决策 |
| 合规审计员 → 主 Agent | 审计报告 | 工作区修改+报告 | 主 Agent 验收证据链 |
| 监控员 → 主 Agent | 监控报告 | .agent/monitor-report.md | 主 Agent 决策扩充 |
| 生命周期管理员 → 主 Agent | 分级报告 + 台账分级 | .agent/lifecycle-report.md + 台账 | 主 Agent 决策加码/止损 |
| 反馈分析师 → 主 Agent | 反馈报告 | keyword-results/{game}-feedback.md | 主 Agent 决策补缺口 |

### 每个交接的检查规则

**建站协调员 → QA（核心接力）：**
- 建站协调员交：站点目录路径 + 新增攻略清单 + 选品评分依据
- QA 检查：residue 扫描 + 30%+ 抽样 + 编造检查 → PASS/FAIL
- FAIL 退回：编造内容退回建站协调员修复；断言问题转合规审计员

**关键词研究员 → 建站协调员：**
- 交：关键词报告（总数/主题簇/命中率/优先主题）+ 页面矩阵 + 素材文档
- 建站协调员检查：主题覆盖是否完整（≥5 簇）；关键词 <20 时退回重采集；
  矩阵 P0 行 ≥5 且每行有目标词与搜索意图、分组过 MECE；
  每页素材 ≥2 源且 ≥1 官方（规则见 `docs/STRATEGY-内容生产.md` 第二、三节）

**候选分析员 → 主 Agent：**
- 交：`selection-{date}.md` + 候选池四维分数/结论
- 主 Agent 检查：每分有依据；6 条查询全跑；`P ≥ 3` 是否硬放弃；缺数据是否写 `[待确认]`
- 口径见 `docs/STRATEGY-选词与评分.md`

**侦察员 → 候选分析员：**
- 交：候选池新增行（状态 `待分析`）+ discovery 报告
- 分析员检查：证据链接是否齐全（Steam 页必填）；硬筛理由是否成立；
  不齐全就退回补，但 MUST NOT 让侦察员代打分

## 九、职责重复检查

| 潜在重复 | 判断 |
|---------|------|
| QA 审核员 vs 合规审计员 | 已划分：QA 只报告不修复（建站质量门）；合规审计员报告+修复（存量改造） |
| 侦察员 vs 候选分析员 | 已划分（2026-10-25）：侦察只发现+硬筛+证据入池；分析员做竞争/需求/内容/生命周期评分与成本。**发现者不打分**（复核实证：6 候选重评 4 个改分） |
| 候选分析员 vs 关键词研究员 | 无重复：分析员只读关键词报告的 5 个数字与分类统计，不采词；研究员不判断值不值得建 |
| 候选分析员 vs 主 Agent | 无重复：分析员给结论与依据，主 Agent 做派发与验收，不改分 |
| 侦察员 vs 关键词研究员 | 无重复：侦察是发现，关键词是需求调研；侦察不再做 Top 15 收割，全部走验证轮 |
| 监控员 vs 反馈分析师 | 无重复：一个看流量数据，一个看用户内容；但都在为「扩充决策」服务，可共享决策会议（主 Agent） |
| 生命周期管理员 vs 性能监控员 | 已划分（2026-10-25）：监控员看趋势与异常（发生了什么），生命周期管理员定分级与止损（投不投）。数据源相同，**职责与输出文件不同**，为控制单岗位上下文刻意分开 |
| 主 Agent vs 建站协调员 | 无重复：主 Agent 不建站，只验收部署 |
