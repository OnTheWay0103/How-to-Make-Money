## 四、完整工作链（三条链路）

```
链路 A — 建站（活跃）：
侦察员 → CANDIDATE-POOL.md → 主Agent决策 → 关键词研究员 → keyword-results/
→ 建站协调员 → 站点 → QA审核员 → QA报告 → 主Agent验收 → 部署 → STATS更新

链路 B — 合规改造（活跃）：
主Agent → 合规审计员 → 审计报告 → 主Agent验收 → commit/deploy → 线上验证

链路 C — 运营优化（暂停，定时任务恢复后激活）：
监控员 → monitor-report → 主Agent决策 ──┐
反馈分析师 → feedback报告 → 主Agent决策 ─┤→ 建站协调员（扩充）→ QA → 部署
```

## 八、交接协议（文件契约）

### 交接文件契约表

| 交接 | 交接物 | 文件 | 检查方 |
|------|--------|------|--------|
| 侦察员 → 主 Agent | 候选清单 | CANDIDATE-POOL.md | 主 Agent 复核评分依据 |
| 关键词研究员 → 建站协调员 | 关键词报告 | keyword-results/{game}.md | 建站协调员检查主题覆盖 |
| 建站协调员 → QA | 站点目录 | games-site/{site}wiki/ | QA 按 Profile 全检 |
| QA → 主 Agent | QA 报告 | .agent/qa-report.md | 主 Agent 按 PASS/FAIL 决策 |
| 合规审计员 → 主 Agent | 审计报告 | 工作区修改+报告 | 主 Agent 验收证据链 |
| 监控员 → 主 Agent | 监控报告 | .agent/monitor-report.md | 主 Agent 决策扩充 |
| 反馈分析师 → 主 Agent | 反馈报告 | keyword-results/{game}-feedback.md | 主 Agent 决策补缺口 |

### 每个交接的检查规则

**建站协调员 → QA（核心接力）：**
- 建站协调员交：站点目录路径 + 新增攻略清单 + 选品评分依据
- QA 检查：residue 扫描 + 30%+ 抽样 + 编造检查 → PASS/FAIL
- FAIL 退回：编造内容退回建站协调员修复；断言问题转合规审计员

**关键词研究员 → 建站协调员：**
- 交：关键词报告（总数/主题簇/命中率/优先主题）
- 建站协调员检查：主题覆盖是否完整（≥5 簇）；关键词 <20 时退回重采集

**侦察员 → 主 Agent：**
- 交：候选池更新 + discovery 报告
- 主 Agent 检查：评分依据可追溯；wiki 检查含非英文站（DOLOC TOWN 教训）

## 九、职责重复检查

| 潜在重复 | 判断 |
|---------|------|
| QA 审核员 vs 合规审计员 | 已划分：QA 只报告不修复（建站质量门）；合规审计员报告+修复（存量改造） |
| 侦察员 vs 关键词研究员 | 无重复：侦察是选品，关键词是调研；但侦察的 Phase 2 有简化版关键词收割，正式建站前仍需关键词研究员完整跑一遍 |
| 监控员 vs 反馈分析师 | 无重复：一个看流量数据，一个看用户内容；但都在为「扩充决策」服务，可共享决策会议（主 Agent） |
| 主 Agent vs 建站协调员 | 无重复：主 Agent 不建站，只验收部署 |

## 十、哪一步需要人确认

1. **AdSense 申请**：用户手动提交（进行中 — 两站已提交）
2. **建站决策**：评分 15-17 分边界值
3. **大改方案**：合并/删除内容、站点重构
4. **对外发布**：任何对外声明
5. **收款配置**：税务信息、PIN 验证
