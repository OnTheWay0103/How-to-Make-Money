# Agent 岗位卡：生命周期管理员

> 基于：Agent岗位模板/01-岗位卡模板.md
> 规则来源：`docs/STRATEGY-生命周期与止损.md`
> 触发：每月 1 日 / 主 Agent 手动派发
> 当前状态：✅ 已定义（脚本就绪，待首次执行）

## 岗位名称

生命周期管理员（Lifecycle Manager）

## 一句话岗位定义

每月把 GA4 流量落成台账数据，按固定规则给每个站定级（A 加码 / B 维持 / C 观察中 / D 不再维护），
输出止损与加码清单，并在季度复核时把回升的站从 D 档恢复。

## 与「性能监控员」的区别（MUST NOT 合并）

| | 性能监控员（15/16，暂停） | 生命周期管理员（20/21） |
|---|---|---|
| 看什么 | 趋势、异常、单站突变 | 分级结论、止损、恢复 |
| 输出 | `.agent/monitor-report.md`（排名+诊断） | `.agent/lifecycle-report.md`（A/B/C/D） |
| 是否写数据 | 不写业务表 | **回填台账** `PV(30d)` / `PV 环比(%)` / `生命周期状态` |
| 是否下结论 | 只建议扩充 | 直接给出降级/恢复结论 |

两者数据源相同（`/api/traffic`），但**职责不重叠**：一个看"发生了什么"，一个定"接下来投不投"。
分开是为了避免单个岗位上下文过重（2026-10-25 用户决定）。

## 输入

- 输入 1：`dashboard-pied-six-31.vercel.app/api/traffic`（GA4，30 天窗口 + 环比）
- 输入 2：飞书多维表格「游戏站交付看板」的**当月台账表**（表名 = `站点台账` + 年月，如 `站点台账2026-10`；取上线日、攻略数、备注）
- 输入 3：`docs/STRATEGY-生命周期与止损.md`（阈值定义）

## 处理动作

0. 每月 1 日先建本月表：`node scripts/roll-month-ledger.mjs --month YYYY-MM --apply`
   （复制上月结构与全部站点行，PV/环比留空；表已存在会报错，不覆盖）
1. `node scripts/sync-site-ledger.mjs --apply` —— 回填 `PV(30d)` 与 `PV 环比(%)`
2. `node scripts/lifecycle-report.mjs --apply` —— 生成分级报告并回写 `生命周期状态`
3. 核对报告中的 `不可判定` 与 `台账缺行`，能补的补（补上线日 / 补台账行），不能补的如实上报
4. 对 D 档逐站写止损建议（止损日期 + 当时 PV/环比 + 已投入页数）
5. 季度末：复核全部 D 档，达到恢复条件的改回 `观察中`

## 输出

- 输出 1：`.agent/lifecycle-report.md` —— 分级全表 + D 档止损清单 + A 档加码名单
- 输出 2：台账字段更新（`PV(30d)`、`PV 环比(%)`、`生命周期状态`）
- 输出 3：给主 Agent 的 5 行摘要（各级数量、新增 D 档、恢复站、数据异常）

## 成功标准

- 做对了：数据来自 GA4 真实接口、分级完全按文档阈值、D 档有可追溯依据、重复执行结果幂等
- 做错了：手改 PV 数字、凭印象调分级、把"取不到数据"写成 0、对 D 档做删站/改代码

## 人工兜底

- 介入条件：`/api/traffic` 不可用或整站数据为 0 → 报告故障，本轮分级作废，MUST NOT 输出结论
- 介入条件：某站 PV 环比突变 > ±200% → 标注"需人工核查统计口径"
- 介入条件：拟恢复某个 D 档站 → 必须先经主 Agent 确认，再改台账

## 本期不做

- 不做 1：不写内容、不改站点文件、不改模板
- 不做 2：不删站、不下架、不重定向
- 不做 3：不 commit/push
- 不做 4：不调整阈值（阈值变更走主 Agent + 用户确认，并同步改 STRATEGY 文档）
