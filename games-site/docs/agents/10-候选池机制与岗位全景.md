## 一、候选池是如何工作的

### 数据流

```
侦察 Agent（discover-games skill）
  ├─ WebSearch 多源搜索（Steam wishlist/SteamDB/新品）
  ├─ 自动筛选（跳过 AAA/纯竞技/超休闲/已停服）
  ├─ Wiki 竞争检查（Top 5 候选逐个搜索）
  └─ 写入 CANDIDATE-POOL.md（覆盖候选清单）
        │
        ▼
主管 Agent（coordinator skill）
  ├─ 读取 CANDIDATE-POOL.md
  ├─ 评分筛选（≥ 15 分建站门槛）
  └─ 决策：建站 / 扩充 / 观望
```

### 评分体系（evaluate-game skill，20 分制）

| 维度 | 分值 | 标准 |
|------|:--:|------|
| 搜索需求 | /5 | 关键词量、玩家搜索意图 |
| 生命周期 | /5 | 更新节奏、长尾潜力 |
| 内容扩展 | /5 | 可写攻略深度 |
| 竞争结构 | /5 | wiki 覆盖、攻略站密度 |

### 问题：旧 skill 和新岗位卡是两套体系

| | 旧体系（.claude/skills/，7/31 设计） | 新体系（docs/agents/，8/21 建立） |
|---|---|---|
| 格式 | Skill 文件（how-to 步骤） | 岗位卡 + Profile（MUST 规则 + 兜底 + 边界） |
| 角色数 | 8 个 | 4 个 |
| 侦察员 | 有（discover-games 68 行） | ❌ 无 |
| 评估员 | 有（evaluate-game 50 行） | ❌ 无 |
| 监控员 | 有（monitor-performance 98 行） | ❌ 无 |
| 反馈分析师 | 有（analyze-player-feedback 193 行） | ❌ 无 |

### 结论：侦察员值得做岗位卡

理由：
1. **候选池质量直接影响建站决策** — DOLOC TOWN「零 wiki」表述不准确（中文灰机 wiki 存在）就是侦察不够细
2. **侦察是重复性岗位** — 候选池空了就调用，频率最高
3. **评分标准需要 MUST 规则固化** — 什么算「零 wiki 竞争」？什么分值得建站？现在散落在多个 skill 文件

## 二、Google AdSense 申请流程

### 前置条件（我们已完成度）

| 条件 | 要求 | 我们的状态 |
|------|------|:--:|
| 内容 | 15-30 篇原创深度文章 | ✅ Sephiria 29 篇（P0+P1+P2 完成） |
| 必要页面 | About/Contact/Privacy | ✅ 全部齐全 |
| HTTPS | 强制 | ✅ Vercel 自动 |
| 网站年龄 | 建议 1-2 个月 | ✅ Sephiria 7/21 上线，已 1 个月 |
| 流量 | 50-100 自然访客/天 | ✅ PV 10,172/30天 ≈ 339/天 |
| 验证代码 | head 中 adsbygoogle.js | ✅ 已在 layout.tsx（ca-pub-7211682665758448） |
| ads.txt | 根目录声明 | ✅ 已就位 |

### 申请步骤（约 6 步）

1. 访问 adsense.google.com → 登录 Google 账号
2. 点击「开始使用」→ 填写网站 URL（**https://sephiriawiki.vercel.app**）
3. 填写国家/地区 + 收款信息（姓名须与身份证一致，选定后不可改）
4. Google 提供验证代码 → 我们已提前放置（layout.tsx 的 adsbygoogle.js）
5. 后台状态变为「已确认」→ 点击「提交审核」
6. 等待审核 **1-14 天**（通常 1-2 周），结果发 Gmail

### 审核期间注意事项

- MUST 保持网站正常运营，不大改版
- MUST 维持稳定发文节奏（每周 1-2 篇）
- MUST NOT 自点广告、买流量
- MUST NOT 移除验证代码

### 通过后

- Auto Ads 自动广告（最简单）或手动广告单元
- 收款：累计 $100 → 税务信息（W-8BEN）→ PIN 验证（实体信件）

## 三、全工作流岗位拆分梳理

### 完整业务链路

```
① 选品 → ② 关键词 → ③ 建站 → ④ QA → ⑤ 部署 → ⑥ 监控 → ⑦ 反馈 → ⑧ 合规 → ⑨ 变现
```

### 岗位全景（建议最终版）

| # | 岗位 | 对应 skill/文件 | 职责 | 岗位卡状态 |
|:--:|------|------|------|:--:|
| 0 | **主 Agent 统筹** | coordinator | 调度/验收/部署/闭环 | ✅ 07/08 |
| 1 | **游戏侦察员** | discover-games + evaluate-game | 搜索→筛选→评分→候选池 | ❌ **待建** |
| 2 | **关键词研究员** | harvest-keywords | Google Suggest 收割→keyword-results/ | ❌ **待建**（可并入侦察员） |
| 3 | **建站协调员** | build-game-site | 建站+内容扩充 | ✅ 03/04 |
| 4 | **QA 审核员** | quality-assurance | 残留扫描+编造检查 | ✅ 05/06 |
| 5 | **性能监控员** | monitor-performance | PV 分析→标记重点站→扩内容建议 | ❌ **待建** |

### 岗位合并建议

- **侦察员 + 评估员 = 1 个岗位**（evaluate-game 只有 50 行，是侦察的子步骤）
- **关键词研究员 + 侦察员 = 可合并**（关键词收割是评估的 Phase 2）或保持独立（建站前专用）
- **监控员 + 反馈分析师 = 可合并为「数据运营员」**（都是数据驱动决策）或保持独立

### 执行建议

1. 先为「游戏侦察员」建岗位卡（候选池是流水线源头，最值得固化）
2. 监控员和反馈分析师因为定时任务暂停，优先级放低
3. 关键词研究员并入侦察员岗位卡（作为其中一步），不单独建
