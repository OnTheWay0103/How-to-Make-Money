> 基于：Agent岗位模板/01-岗位卡模板.md
> 驱动：auto-build-site.sh（launchd 定时）+ 主 Agent 手动触发
> 当前状态：▶️ 已恢复（2026-08-22 起，BUILD-001 新 Agent 管线；AdSense 合规红线永久有效）

## 岗位名称

建站协调员（Site Coordinator）

## 一句话岗位定义

当收到「建站任务」（定时触发或手动指令）时，自动搜索热门游戏 → 评估建站价值 → 生成站点 → 部署上线，并输出建站记录。

## 输入

- 输入 1：游戏搜索条件（Steam 热门/愿望单/新发售）
- 输入 2：候选评估标准（评分 20 分制：热度/竞争/上线时间等）
- 输入 3：参考站点模板（已有 wiki 的结构）

## 处理动作

1. 发现游戏：搜索 Steam 热门游戏（发售/EA 上线/高 wishlist）
2. 评估：按评分体系打分，达标才建站
3. 内容生成：按游戏类型生成攻略（含 QA 审核环节）
4. 站点初始化：复制模板站点结构
5. 配置：GA4 + GSC + Dashboard 注册
6. 部署：Vercel 部署
7. 记录：更新 STATS.md + build-history.json

## 输出

- 输出 1：新站点（games-site/<gamename>wiki/）
- 输出 2：QA 报告（.agent/qa-report.md 更新）
- 输出 3：STATS.md 更新
- 输出 4：建站日志（~/Library/Logs/auto-build-site/）

## 成功标准

- 做对了：站点构建零错误、部署成功、GA4/GSC/Dashboard 三步配置齐全
- 做错了：内容编造（虚构 Boss/武器/评分）、跨站污染、QA 未通过仍部署

## 人工兜底

- 介入条件：评分接近阈值的游戏（≥17 分边界情况）
- 介入条件：QA 发现编造内容时停止建站
- 检查环节：QA 报告提交后主 Agent 复核

## 本期不做

- 不做 1：不建评分 <15 分的站
- 不做 2：不写 "Patch X.XX" 版本声明（无法验证）
- 不做 3：不编造游戏数据（HP/damage/评分数值）
- 不做 4：不在 AdSense 合规改造期间自动运行（已暂停）
