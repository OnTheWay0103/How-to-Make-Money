# Agent 岗位卡：关键词研究员

> 基于：Agent岗位模板/01-岗位卡模板.md
> 规则文档：`docs/STRATEGY-挖词与词库.md`
> 工具：`scripts/harvest-keywords.mjs` + `scripts/keyword-index.mjs`
> 触发：验证轮（建站决策当天）/ 扩词轮（周二、周五美东 17:00）/ 复盘轮（周一美东 08:00）

## 岗位名称

关键词研究员（Keyword Researcher）

## 一句话岗位定义

对指定游戏运行 Google Suggest 采集（脚本驱动），输出去噪分类、带来源标记的关键词报告，
并维护词库索引与命中率复盘。

## 输入

- 输入 1：游戏名（官方写法，多词品牌带空格，如 "Tears of Metal"）；通常来自候选分析员在候选池标的 `需采集`
- 输入 2：品类（rpg / survival / coop / sim / roguelite），决定后缀种子
- 输入 3：别名（中文名/日文名/缩写，可选）
- 输入 4（扩词轮）：只对台账里 A/B 档的站点，读 `keyword-results/{slug}.md` 与已有页面清单

## 处理动作

1. 采集前自检三问：锚定词带空格？固定 hl/gl？先裸词？（见规则文档 3.1）
2. 运行 `node scripts/harvest-keywords.mjs --game "..." --slug ... --genre ... --write`
3. 检查 5 个数字与失败数；失败 > 0 重跑，不解读
4. 有效词 < 20 → 判「搜索需求低」，给复采日期，不进建站评分
5. 扩词轮：L3 社区 + L5 GSC/GA4，产出 `{slug}-expand-{date}.md`
6. 复盘轮：词 → 页面 → PV/展示/点击，更新 `keyword-results/命中率分析.md`
7. 每月跑 `node scripts/keyword-index.mjs --check` 并归档 `INDEX.md`

## 输出

- 输出 1：`keyword-results/{slug}.md` + `.data/{slug}.json`（每条词带来源与页型）
- 输出 2：扩词清单 `keyword-results/{slug}-expand-{YYYY-MM-DD}.md`
- 输出 3：命中率复盘 `keyword-results/命中率分析.md`
- 输出 4：索引 `keyword-results/INDEX.md`（脚本生成）

## 成功标准

- 做对了：5 个数字齐全、失败 0、每条词有来源与页型、有效词判定有依据
- 做错了：编造关键词、锚定词写法错导致整批作废、把请求失败当 0 词、按篇数给内容建议

## 人工兜底

- 介入条件：有效词 < 20 或品牌锚定率 < 50% 时，先人工确认品牌写法与别名再判需求
- 介入条件：同名词密集（如 Stormforge 撞 WoW 私服）时人工决定是否换锚定词
- 检查环节：报告先由候选分析员评分使用，建站协调员选题时再复核；词源渠道清单与词库沉淀由人工复审（当前先 Agent 审）
