# 选词与评分

> 2026-10-25 定稿。对照「游戏站建站全流程清单」第 3 部分（三、选词）逐节点落地。
> 本文是**判断标准**；执行人是候选分析员（`docs/agents/22` / `23`），
> 上游是游戏侦察员（`docs/agents/11` / `12`）与关键词研究员（`docs/agents/13` / `14`）。
> 口径来源：本文自定 + 生财有术公开帖子对照（见第九节，逐条标了出处）。

## 一、选词分工（先分清谁做什么）

| 环节 | 谁做 | 产出 | 不做 |
|---|---|---|---|
| 发现候选 | 侦察员 | `CANDIDATE-POOL.md`（状态 `待分析`） | **不评分、不查 wiki、不采词** |
| 硬门槛初筛 | 候选分析员 | 状态改 `放弃` 或 `需采集` | 不做四维打分 |
| 品牌词采集 | 关键词研究员 | `keyword-results/{slug}.md` | 不判断值不值得建站 |
| 四维评分 + 竞争 + 需求 + 成本 | 候选分析员 | `keyword-results/selection-{date}.md` | 不建站、不改站点 |
| 建站决策 | 主 Agent | 派发建站协调员 | — |

**为什么拆开**：侦察员一天要过 100+ 个候选，如果每个都查 wiki、采词、打分，一轮跑不完；
而且「发现」和「判断」是两种心态——发现要宽，判断要严，同一个 Agent 做容易自我确认。
2026-10-24 的复核实证：6 个候选重评后 4 个改分（Emberville 18→15、Stormforge 17→15、
Loftia 16→14、Draemony 16→13），说明**评分者与发现者分开是必要的**。

## 二、四维口径（节点 11）

### 2.1 四个维度各 0–5 分，总分 20

| 维度 | 回答什么 | 主要证据 | 5 分长什么样 |
|---|---|---|---|
| **需求** | 有人搜吗，搜的是攻略吗 | Suggest 有效词 + 攻略型词占比 + 第三方信号 | 有效词 ≥60 且攻略型占比 ≥50% |
| **竞争** | 首页有没有人认真做 | SERP 前 10 的专门攻略站数量与厚度 | 没有专门攻略站 |
| **内容扩展** | 能不能写 20 页以上 | 可核验的机制/角色/物品/Boss 数量 | 30+ 页且 5 类各 5 条 |
| **生命周期** | 现在做还来不来得及 | 发售日/更新日 + Trends 曲线形状 | 发售 ≤8 周且曲线上升 |

原「变现」维度**移出评分**，并入节点 16 成本模型（理由：变现在单站层面几乎不可预估，
把它当评分项只会诱导给「感觉能赚钱」的游戏打高分）；原「可行性」并入内容扩展。

### 2.2 需求（0–5）

依据是 `keyword-results/{slug}.md` 的 5 个数字，不另采。

| 分 | 有效词 | 附加条件 |
|:--:|---|---|
| 5 | ≥ 60 | 攻略型词占比 ≥ 50%；≥ 3 类页型各 ≥ 5 词 |
| 4 | 40–59 | 攻略型词占比 ≥ 40% |
| 3 | 25–39 | ≥ 3 类页型各 ≥ 3 词 |
| 2 | 20–24 | 刚过判定线 |
| 0 | < 20 | **门禁淘汰**，不进评分（规则见 `docs/STRATEGY-挖词与词库.md` 4.2） |

**攻略型词** = Codes / Tier List / Best-Ranking / Build-Class / Weapons-Gear / How-to /
Guide-Beginner / Co-op-Multiplayer。
**非攻略型词** = Info/发售平台 + Other。
`攻略型占比 = 攻略型词数 / 有效词数`。

**三个修正（MUST 执行，写在评分依据里）**：

| 修正 | 触发 | 动作 | 出处 |
|---|---|---|---|
| **发售日陷阱** | 攻略型占比 < 30% | 需求**封顶 3** | 袁锐钦：子关键词清一色 release/trailer → 没攻略需求 |
| **单源** | 需求只有 Suggest 一个来源 | 需求**封顶 3**，先观察一周 | 袁锐钦「双源规则」 |
| **判定线** | 有效词 < 20 | 直接淘汰，不评分 | 我方规则（2026-10-25） |

> 样本：`tearsofmetal` 164 个有效词，其中 Info/发售平台 70 条，**攻略型占比 10.4%** —— 典型
> 「大家只想看什么时候发售」。这类站上线后流量随发售窗口衰减，属预期内，不是执行失败。
> 当前只有 1 个新格式样本，30% 这条线记为**待校准**（2027-01 复盘）。

### 2.3 竞争（0–5）

**只算「专门攻略站」**（定义见第三节）。先数：

- `T` = 厚站数量（独立域名 + 围绕该游戏 + 覆盖 ≥3 类攻略页 + 4 周内有更新）
- `t` = 薄站数量（同上但只覆盖 1–2 类，或 >8 周未更新）
- **压力值 `P = T + 0.5 × t`**

| P | 分 | 判断 |
|:--:|:--:|---|
| 0 | 5 | 空位，立即建 |
| (0, 1] | 4 | 只有薄站，可以切 |
| (1, 2] | 3 | 1 家厚站或 2 家薄站，可做但要有差异化 |
| (2, 2.5] | 2 | 2 家厚站，难 |
| (2.5, 3) | 1 | 接近饱和 |
| ≥ 3 | 0 | **硬放弃**，不进评分（林广恩阈值：前三页 3 个以上专门攻略站 → 跳过） |

**规则细节**：

- SERP 结果不足 10 条，或前 10 大多是 YouTube / Reddit / 论坛帖 → 按 P=0 处理（袁锐钦）。
- Fandom 不是「有就放弃」，而是**看厚度**：该游戏 Fandom 页 codes/tier list 齐全且近期更新 → 厚；
  只有骨架或停更 → 薄（袁锐钦：「Fandom 有站但内容薄、更新慢 → 可以切」）。
- 官方 wiki：权威但通常缺 codes / 强度榜 / 具体数值 → 多数按薄计；若它同时覆盖攻略型页面且更新 → 按厚计。
- 意图错位：前 10 排满了不代表都在答题。若排在前面的整页在答另一件事（如全是「下载/配置」而
  搜索词是「codes」），该结果**不计**，并在依据里写「意图错位」（袁锐钦）。
- **只算英文**（`hl=en&gl=us`）。中文/日文有专门站不直接构成英文竞争，但说明攻略生态成熟 →
  竞争 0 分项不额外扣；**中文/日文明显空缺 → 内容扩展 +1**（林广恩多语言空间）。

### 2.4 内容扩展（0–5）

**先过硬门槛**：这游戏有没有足够的机制/物品/角色/Boss/系统可写？没有 → 直接淘汰（袁锐钦硬门槛）。

| 分 | 可写独立页数 | 附加 |
|:--:|---|---|
| 5 | ≥ 30 | ≥ 5 个可写类别，每类 ≥ 5 条具体实体 |
| 4 | 20–29 | ≥ 4 个类别 |
| 3 | 12–19 | ≥ 3 个类别 |
| 2 | 6–11 | — |
| 1 | 3–5 | 只能做短站，上线后大概率停在 5 页 |
| 0 | < 3 | **淘汰** |

**「可写」= 有可核验来源**（官方公告 / 商店页 / 官方 wiki / 社区 wiki / 评测），
不是搜索建议里出现过（`12-Profile-游戏侦察员.md`「内容可写性分级规则」沿用：搜索建议只证明需求，不证明存在）。
林广恩的通过标准是「能支撑 20+ 页独立内容」—— 与本表的 4 分线一致。

### 2.5 生命周期（0–5）

| 分 | 状态 |
|:--:|---|
| 5 | 已发售 ≤ 8 周且 Trends 上升或高位平稳；或未发售、定档 ≤ 8 周且 wishlist 强 |
| 4 | 发售 8–16 周；或未定档但有强 wishlist / demo |
| 3 | 发售 16–26 周 |
| 2 | 发售 26 周–12 个月，无大版本更新；**或 Trends 单峰暴涨后回落（陷阱词）** |
| 1 | 发售 > 12 个月且无更新计划 |
| 0 | 已停服 / 官方停更 |

依据顺序：Steam 商店页发售日 → 官方公告更新日 → SteamDB 在线曲线 → Google Trends 28 天。
查不到就写 `[待确认]`，**MUST NOT 猜**。

### 2.6 分级与分流

| 总分 | 结论 | 动作 |
|:--:|---|---|
| ≥ 17 | **可建** | 进建站队列，主 Agent 优先派发 |
| 15–16 | **观察** | 按上线窗口决定；缺一维数据就补齐再来 |
| 12–14 | **低优先** | 留在池里，等发售/更新/数据变化 |
| < 12 | **放弃** | 划删除线 + 写放弃原因，保留决策轨迹 |

**缺依据的维度按 0 计**（不是按平均分给）。每一分 MUST 带一句话依据 + 链接，
写在 `selection-{date}.md` 里；候选池只放分数和报告链接。

## 三、竞争检查（节点 13）

### 3.1 什么叫「专门攻略站」

| 类别 | 定义 | 例 | 计不计 |
|---|---|---|---|
| **专门攻略站·厚** | 独立域名 + 内容围绕该游戏 + 覆盖 codes/tier/角色/物品等 ≥3 类 + 4 周内更新 | Game8、Pro Game Guides、Deltia's Gaming、AllThings.How、内容厚且更新的 Fandom 页 | 计 1（`T`） |
| **专门攻略站·薄** | 同上但只覆盖 1–2 类，或 >8 周未更新 | 小站、骨架 wiki、停更站 | 计 0.5（`t`） |
| **非专门** | 大站单篇、Reddit / Steam 社区 / YouTube / 论坛、Steam 商店页、PCGamingWiki、聚合列表页 | IGN 的一篇评测、Steam 讨论区 | **不计** |
| **官方 wiki** | 厂商官方 wiki | — | 按 3.1 细则折算 |

> 林广恩的原始定义是「独立域名、内容围绕这个游戏的网站」，并明确 Reddit 帖、Steam 社区帖、
> 通用 wiki（Fandom）的**子页面**不算「专门攻略站」。我们稍作调整：Fandom 该游戏页在**厚**的时候
> 计入——因为它确实在竞争同一批 codes/tier 词，按「不计」会低估竞争。

### 3.2 固定查询模板（6 条，MUST 全跑）

| # | 语言 | 查询 | 看什么 |
|:--:|---|---|---|
| 1 | EN | `{Game} wiki` | wiki 生态 |
| 2 | EN | `{Game} guide` | 攻略站 |
| 3 | EN | `{Game} codes` | 最高价值词型的竞争 |
| 4 | ZH | `{中文名或 Game} 攻略` | 中文站 |
| 5 | ZH | `{Game} wiki` | 中文 wiki（灰机/B站/萌娘） |
| 6 | JA | `{Game} 攻略` | 日文站（wikiwiki.jp / atwiki.jp） |

每条记录：**前 10 名的域名 + URL + 归类（厚/薄/非专门）**。
MUST NOT 只跑 1 条 EN 就写「零 wiki」；MUST NOT 用「搜索无结果」代替「没有专门站」（要看是否有 <10 条结果）。

产出：`keyword-results/selection-{YYYY-MM-DD}.md`，每个候选一节。

## 四、品牌词污染（节点 14）

直接用验证轮报告的数字，不重新采集：

| 品牌锚定率 | 判断 | 动作 |
|---|---|---|
| ≥ 50% | 通过 | 正常进四维评分 |
| 30–50% | 可疑 | 先查锚定词写法 / 别名（中文名、日文名、缩写）→ 重采一次 |
| < 30% | 污染 | 判「品牌不成立或撞名严重」→ 放弃，或换官方写法重采后再判 |

锚定率 < 30% 时 MUST NOT 用「有效词少」直接判需求低——先排除 `tearsofmetal`（无空格）返回
`tears of themis` 那类错误。规则细节见 `docs/STRATEGY-挖词与词库.md` 3.1 / 4.2。

## 五、需求验证（节点 15）

三道闸门全过才进四维评分的 4 分以上；任一不过只能落 2–3 分或淘汰：

| # | 闸门 | 通过线 | 数据来源 |
|:--:|---|---|---|
| 1 | 有效词 | ≥ 20 | `keyword-results/{slug}.md` 头部 |
| 2 | 页型覆盖 | ≥ 3 类页型各 ≥ 3 词 | 同报告分类统计表 |
| 3 | 第三方信号 | ≥ 1 个（wishlist / 评测数 / CCU / Trends 其一） | Steam 商店页、SteamDB、Google Trends，**带日期和链接** |

**双源规则**：需求判定至少 2 个独立来源（Suggest 算 1 个），只有单一来源的需求封顶 3 分，
先观察一周再定（袁锐钦「双源规则」）。
**未知值写 `[待确认]`**：MUST NOT 用估算数字补齐，MUST NOT 把「查不到」当 0 或当「没有」。

## 六、成本与回本（节点 16）

### 6.1 成本模型

| 项 | 口径 | 当前值 |
|---|---|---|
| 域名 | 当前用 `*.vercel.app` 子域 | 0 元（若改自有域名：~10–15 元/年首年，续费另算） |
| 托管 | Vercel 免费版 | 0 元（注意 100 次部署/UTC 日上限） |
| 内容生成 | token 消耗，按实际记录 | 建站后回填实测值 |
| 人工 | 建站 + 验收 | 目标 ≤ 6 小时/站（记进台账「实际人工小时」） |
| **合计** | 元/站 | **实测回填，不预估** |

### 6.2 回本口径

```
回本 PV = 总成本 / (RPM / 1000)
```

- RPM 参考：游戏/娱乐类页面 **$1–5 / 千次页面浏览**（第三方公开基准，2026-08 检索，非承诺）。
  按上限与下限各算一次，给区间，**MUST NOT 取单点值当结论**。
- 我们自己的 RPM 用 `node scripts/adsterra-stats.mjs --days 30` 跑出 30 天数据后回填，届时替换第三方区间。
  （2026-10-25 起 AdSense 暂缓、只走 Adsterra，必须用 Adsterra 实测值，MUST NOT 继续拿通用区间当结论。）
- **组合回本，不是单站回本**：按 RPM $1–5，30 天 300 PV 的跑通线约合 $0.3–1.5，
  覆盖不了一个域名。真实回本靠「多站里少数站」——所以台账口径是组合亏盈，不是逐站必须回本。
- MUST NOT 用「千万展示月入数万美元」这类极端案例当基准。

台账（`站点台账YYYY-MM`）新增列：`建站成本(元)`、`实际人工小时`、`预估回本PV`。
由建站协调员建站后填，生命周期管理员月度复核。

## 七、分析轮（排期与产出）

| 项 | 规则 |
|---|---|
| 时间 | **美东 17:30**（紧跟发现轮·晚 17:00），cron 设 `TZ=America/New_York` |
| 触发 | 候选池 `待分析` ≥ 5 个；或主 Agent 手动 |
| 频率 | 默认每天 1 次；候选少的日子跳过 |
| 产出 | `keyword-results/selection-{YYYY-MM-DD}.md` + 候选池回填 |

北京时间等价：次日 05:30（夏令时）/ 06:30（冬令时），落在 DeepSeek 半价时段内。

**分析轮的完整动作**：

1. 读候选池 `待分析` 条目。
2. **硬门槛**：内容可写性不满足 → 直接 `放弃`，写原因。
3. 没有 `keyword-results/{slug}.md` 的 → 标 `需采集`，等关键词研究员跑验证轮。
4. 跑 6 条竞争查询；读验证轮报告；查发售日/更新日/Trends。
5. 四维打分（每维一句话依据 + 链接）→ 写 `selection-{date}.md`。
6. 回填候选池：4 个维度分 + 总分 + 结论 + 证据链接。

## 八、与生财有术口径的对照

> 2026-10-25 用 scys MCP 检索「游戏攻略站 / 选品 / 竞争」，取 3 篇可核验的公开帖对照。
> 只采纳与我们可执行工具链对得上的部分；对不上的记为「可选增强」，不硬造数据。

| 生财口径 | 出处 | 我们怎么用 |
|---|---|---|
| 四层漏斗：发现 → 游戏评分 → 需求验证 → 竞争验证 | 袁锐钦《…整条流水线开源了》(2026-08) | 采纳为流程骨架（发现=侦察员，后三层=分析员） |
| 硬门槛：有没有足够机制/物品/Boss 可写 | 同上 | 采纳 → 内容扩展 0 分即淘汰 |
| 需求看 Trends 曲线形状：爬升稳住 vs 单峰 | 同上 | 采纳 → 生命周期 2 分封顶（陷阱词） |
| 需求看子关键词构成：codes/tier/guide vs release/trailer | 同上 | **采纳并量化** → 攻略型词占比（我方新增指标） |
| 双源规则：需求信号 ≥2 个独立来源 | 同上 | 采纳 → 单源封顶 3 分 |
| 竞争三分法：空位 / Fandom 薄可切 / Fandom·Game8 厚且日更放弃 | 同上 | 采纳 → 厚/薄定义 + `P = T + 0.5t` |
| 意图错位：排满不代表答对题 | 同上 | 采纳 → 竞争检查的排除项 |
| 前十 3 个以上专门攻略站 → 跳过 | 林广恩《从 0 到 1 做出游戏攻略站》(2026-09) | 采纳 → P ≥ 3 硬放弃 |
| 内容空间：能支撑 20+ 页独立内容 | 同上 | 采纳 → 内容扩展 4 分线 |
| 热度：SteamDB 火苗 + Trends 28 天明显高于其他候选 | 同上 | 采纳 → 需求/生命周期证据 |
| 多语言：前两页 0 家=蓝海 / 1–2 家=有机会 / 3+ = 跳过；官方本地化决定价值 | 同上 | 采纳 → 中文/日文空缺给内容扩展 +1 |
| KD 0–30 可做，>40 别做（SimilarWeb） | 星野《出海热词站手册》摘要(2026-07) | **不采纳为硬门槛**（我们无付费 KD 工具，不能编数字）；记为可选增强，买了 SimilarWeb/SiteData 再用 |
| 首页认 5 类「谁」：Fandom / 官方 wiki / IGN 类 / Game8 类 / 大站普通页 | 同上 | 采纳 → 就是我们的厚/薄/非专门三分法 |
| RPM 游戏类 $1–5 / 千次浏览 | 袁锐钦 | 采纳为成本模型区间，标注第三方与检索日期 |
| 上线后 4 周 GSC 展示 <100/周且无增长 → 放弃；21 天内没有效词不要硬判 | 林广恩 / 星野 | 与本项目 D+30/60/90 检查点一致，已写进 `docs/STRATEGY-生命周期与止损.md`，本文不重复 |

**没采纳的两条**：0–100 分制（我们的 20 分制已跑通且可解释，换制式会断历史数据）；
KD 数值门槛（工具成本 + 数据不可复核）。

## 九、第三部分各节点的审核方式

| # | 节点 | 审什么 | 证据 | 谁审 | 频率 |
|:--:|---|---|---|---|---|
| 11 | 四维评分 | 每维有依据；缺依据按 0；分级是否正确 | `selection-{date}.md` | 主 Agent 复核 + 人工抽检 | 每轮 |
| 12 | 竞品硬性放弃规则 | `P ≥ 3` 是否执行；有没有「看感觉」放过 | 竞争检查表（域名+URL+归类） | **Agent 审 + 人工复审**（当前仅 Agent） | 每轮 |
| 13 | wiki 竞争检查 | 6 条查询是否全跑；三语是否覆盖 | SERP 记录表 | 主 Agent | 每次 |
| 14 | 品牌词污染 | 锚定率是否达线；低锚定率有没有先查写法 | 验证轮报告头部 | 主 Agent | 每次 |
| 15 | 需求验证 | 三道闸门 + 双源 | 闸门表 + 第三方信号链接 | 主 Agent | 每次 |
| 16 | 单站成本与回本 | 成本是否实测；RPM 是否标来源 | 台账三列 + 计算过程 | **Agent 审 + 人工复审** | 每月 |

三条通用原则：证据链优先、脚本先跑人后看、异常必须显性。
