# How to Join a Friend's Game in Big Walk — Join Codes, Passwords & Fixes

> Live build 1.6.0 / Updated: October 23, 2026

Big Walk has no matchmaking. You either join a friend through your platform's friends list or you use the host's **Join Code**. Since patch **1.6.0** on October 6, 2026, those codes contain both letters and numbers — which sounds trivial until you spend ten minutes typing a letter as a digit.

This guide covers the host side, the guest side, the separate **Session Password**, and the checks that actually fix a code that will not connect.

## Two Ways In

| Route | Who it is for | What you need |
|-------|---------------|---------------|
| **Platform friends list** | Friends on the same platform | An active session visible in the friends-game list |
| **Join Code** | Anyone the host sends the code to, including crossplay friends | The current code, plus the Session Password if one is set |

The friends-list route is the easier one when it works. The Join Code is the fallback that works when the friends list does not show the session — and it is the documented route on the Mac App Store version, which does not use Game Center.

## Where the Host Finds the Join Code

The code is per session, not a permanent account code. That means it changes when the host starts a new session, and an old code from yesterday is worthless.

According to the community-maintained Join Code guide, which cites the official FAQ and version history:

- **Before the session starts**, the Join Code appears in a corner of the **host menu**.
- **After the session has started**, the host opens the in-game menu and selects **Session Details** to see the code again.
- **Session Details** is also where the host can change the session password.

If you are the host and cannot find the code, do not start describing your screen to the guest. Open Session Details and read the code exactly as it appears.

## Where the Guest Enters It

From the main menu, choose the join option and enter the code in the code field. In current builds the option is labelled **Join Game**; the exact label can vary by platform. **[Community-reported]**

Enter the code exactly, including letters, and enter the **Session Password in its own field**. Do not paste the password into the code field or the code into the password field — they are two different values, and mixing them is the most common self-inflicted join failure.

If the code is correct and the password is correct, the guest joins the host's world. There is no lobby to wait in; the session is the world.

## Join Code vs Session Password

These are the two values people confuse most often.

| Value | What it does | Who sets it | Where to find it |
|-------|--------------|-------------|------------------|
| **Join Code** | Identifies the specific session | Generated by the game | Host menu before the session; Session Details after |
| **Session Password** | Gates access to that session | Host | Entered separately by the guest; changed in Session Details |

The official version history says version **1.4.9** requires a Session Password when a host starts a new game. That is a start-of-session requirement, not a replacement for the Join Code. A code still identifies which session you are trying to join; the password proves you are allowed in.

If a world you have hosted before suddenly asks for a password, check whether the prompt is asking you to **create** a password rather than unlock an existing one. Community reports describe players treating a create-password box as a lockout when their save was never locked. Read the prompt before you panic.

## Crossplay and Version Rules

Big Walk supports crossplay across PC, Mac, PlayStation 5, and Nintendo Switch 2. The platform does not change how the code works; it changes how you get the code to the other person and whether an extra subscription is needed.

Two version rules matter:

1. **The first two sections of the version number must match.** For example, 1.6.1 and 1.6.4 can play together; 1.5.x and 1.6.x cannot. Check each device before you blame the code.
2. **Console patches can lag PC patches.** If one side has updated and the other has not, the version check will fail even with a perfect code.

Platform requirements are separate from the code: PS5 players need PlayStation Plus, Switch 2 players need Nintendo Switch Online, and PC/Mac players do not need an extra subscription.

## When the Code Does Not Work

Run the checks in this order. Most failures are solved in the first three.

1. **Is the host actually in the world?** The code exists before the world loads, but a guest cannot join a host who is still sitting in a menu or staring at a connection warning.
2. **Is the code current?** Codes are per session. Ask the host to read it from Session Details again rather than reusing an old message.
3. **Are the code and password in the right fields?** Re-enter both manually. Do not trust autofill.
4. **Do the first two version numbers match?** Update both devices.
5. **Is the host's connection warning showing?** Patch 1.5.1 made the in-game network warning distinguish a **slow** connection from an **unstable** one. Those are different problems: slow is a bandwidth issue, unstable is a drop issue. Read which one you have.
6. **Restart in the documented order.** Community guidance is guest first, then host. This forces both clients to rebuild the session.
7. **Try the platform friends list instead.** If the code path fails but the friends list shows an active game, join from there.
8. **Check for a modded client.** Patch 1.6.0 stopped modded clients from performing certain actions that could disrupt other players on the server. If one player is running mods, that is a variable worth removing.

Patch 1.6.0 also fixed several rare networking issues that prevented connections and improved the error and warning messages. If your game is not on 1.6.0 or later, update before troubleshooting further.

## Password Retry Behavior

Patch 1.5.1 changed one small but useful thing: **the password prompt now clears after a failed attempt.** Before that, a wrong password could leave the field populated, and the next attempt would resubmit the same wrong value. If you are on an older build, clear the field manually between attempts.

The same patch changed the wording of the password prompt on the host menu. If the wording in your build differs from a guide, trust your build.

## Hosting Etiquette and Security

- **Send the code privately.** A public code plus a weak password is an open session.
- **Change the password in Session Details** if the code has been shared too widely.
- **Do not reuse an old code.** It belongs to a session, not to you.
- **Remember where saves live.** Community guidance says save data stays on the host's device, so the host is the person who needs to be available when the group wants to continue. **[Community-reported]**

## Join Code FAQ

**Do I need a code if we are friends on Steam or PSN?** No. Platform friends can join from the friends-game list while the session is active. The code is the fallback and the cross-platform route.

**Do codes work across PC and PS5?** Yes, crossplay is supported. Both players still need matching first-two-section versions and the correct platform subscription.

**Why did my code stop working?** The host started a new session. Codes are per session, so ask for the current one.

**Is the code case-sensitive?** Not documented. Enter it exactly as shown and assume it is. **[Unconfirmed]**

**Can someone join mid-walk?** Mid-session joining is not clearly documented. Plan for everyone to be present at the start. **[Unconfirmed]**

**Where is the password?** It is separate from the code. The host sets it when starting a new game and can change it in Session Details.

## Pre-Join Checklist

- [ ] Host is loaded into the world
- [ ] Code copied from the current session, not an old message
- [ ] Password entered in its own field
- [ ] First two version sections match on every device
- [ ] Platform subscription active where required
- [ ] No modded client in the group
- [ ] If it still fails, restart guest first, then host

The code is not a magic key. It is a session identifier. Treat it as one and most join problems disappear.
