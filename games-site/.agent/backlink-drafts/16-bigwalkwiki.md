A controls page is the first thing a player searches for and the last thing a writer wants to make.

It is not analysis, it is not opinion, and there is nothing to discover. It is also, page for page, one of the most reliably useful things on a new game site: specific intent, immediate answer, no competition worth the name.

## What a bad one looks like

A screenshot of the settings menu, unreadable on a phone, with no text.

That is the whole page on a lot of small sites. It answers nothing for anyone who cannot read the image, is not indexable as text, and breaks the moment the game adds a rebind UI.

## What a good one looks like

- **A table.** Action, default binding, and a short note where the binding is unusual. Text, selectable, copyable.
- **Platform differences.** If the game ships on more than one platform, say which defaults apply where. This is where most pages are simply wrong.
- **The rebinding instructions.** Not everyone knows where the settings live, especially if it is buried.
- **Anything genuinely non-obvious.** A control that is undocumented in-game is worth more than the rest of the page.

That is it. Forty minutes of work, and the page keeps earning for as long as the game's defaults do not change.

## Why it is worth doing on every site

For a small site, the value is not the traffic on this page — it is the fact that it is a real answer to a real query, published early, on a site that otherwise has nothing. It gives the site a chance to be seen at all, and it is one more page that other pages can link to.

There is also a trust effect that is hard to measure but easy to feel: a site with a correct controls table feels maintained. A site without one feels like a template with filler.

## Keep it honest

Two failure modes worth naming:

1. **Copying defaults you have not checked.** Bindings change, and a copied table is wrong in ways nobody notices until a reader complains.
2. **Describing a control you have not used.** If you are not sure what a binding does, write the binding and leave the description out. An empty note is better than a confident wrong one.

The [Big Walk controls and keybindings](https://bigwalkwiki.vercel.app/guides/controls-guide) page on [Big Walk Wiki](https://bigwalkwiki.vercel.app) is built to that spec: a table, platform notes, and nothing invented to fill the page.

It will never be the most-read page on the site. It will be the one that is right on day one, which is a different and scarcer thing.
